# 票据市场日评智能体工作流：任务定义

## 一、目标用户与现有流程

### 目标用户

- 票据交易员
- 交易台分析师

### 现有流程

每天人工收集上海票据交易所数据、央行公开市场操作、SHIBOR/DR 利率，手工计算环比、同比与缺口，手写四模块日评。

### 现有流程的三个问题

1. **数字不可复现、结论无留痕**：计算过程和结论依据缺少可追溯记录。
2. **无独立核验**：生成与核验未分离，缺少独立复核机制。
3. **无中断恢复**：数据更新依赖人工，流程中断后难以续跑，重跑成本高。

## 二、任务产出

每个交易日产出一份《票据市场日评》，包含以下四个模块：

1. 票据供给
2. 缺口分析
3. 票据利率
4. 资金面

每份日评必须标注数据截止时点与各模块数据日期。

## 三、重复触发条件

- **触发时间**：每个交易日 08:30 定时触发。
- **信息截止时点**：T-1 日 23:59。
- **数据使用边界**：本日报只使用 T-1 日及之前已公开的数据。

## 四、阶段划分与依赖

主流程如下：

**S0 数据采集 → S1 口径判定 → S2 确定性计算 → S3 日评生成 → S4 独立核验 → S5 人工批准发布 → S6 持续监测**

主流程前向无环。S4 未通过时，经 Orchestrator 修复任务包回退至 S3，形成有界修订回路。

## 五、允许使用的信息来源

- **上海票据交易所（SHEX）**：票据承兑量、贴现量、交易量、票据利率；如公开渠道无法获取，由用户提供 Excel 更新。
- **中国人民银行**：公开市场操作，包括逆回购投放、到期及净投放。
- **全国银行间同业拆借中心 / CFETS**：SHIBOR、DR001、DR007、R007。
- **中国外汇交易中心（CFETS）**：NCD 二级市场收益率与收益率曲线，作为资金面参照。

### 禁止使用的信息

- 任何客户身份信息
- 持仓明细
- 交易对手名称
- 内部限额原文

## 六、验收标准

以下验收标准全部由代码判定：

1. **数据新鲜度**：快照为预期交易日，四模块所需字段齐全。
2. **数值一致性**：日评正文中每个数字都能在确定性计算结果中找到且相等。
3. **模块完整性**：四个模块齐全，无指标结果之外的数字。
4. **时点合规**：无任何字段的可得时点晚于报告信息截止时点。
5. **可恢复**：中断后从已核验检查点继续，不重复已完成的采集与计算。
6. **验收规则**：同一候选日评连续两轮核验通过方可发布。

## 七、已知局限

- 公开数据为日频聚合，无法刻画日内资金面。
- 部分数据需人工录入，录入时点与口径须在快照中登记。
- 本项目输出为研究参考，不是报价指令，不含交易成本与流动性冲击。

## 八、输入

本章逐阶段登记输入项、来源机构或上游产物、数据格式与格式样例。以下样例仅说明结构，数值、日期、版本号和路径均为示意，不代表真实市场数据或既有文件。

## 九、为何需要持久化工作流，而非一次性脚本

1. **信息截止时点具有硬约束。** 本任务在信息截止时点上有硬约束：08:30 触发时只能拿到 T-1 日及之前已公开的数据。一次性脚本无法保证中途不混入尚未公布的当日数据，必须有持久化的时点判定与检查关卡，逐字段保存并复核 `available_at`、快照清单和判定结果。

2. **跨阶段、跨工具调用的执行需要可恢复状态。** 从采集、口径判定、计算、生成、核验到批准的六阶段跨越多次工具调用。中途失败时，一次性脚本无法知道已完成到哪一步，也就无法在不重复已完成操作的前提下恢复。持久化工作流必须记录阶段状态、输入输出哈希和已核验检查点，从最近的有效检查点续跑。

3. **有界修订与连续核验要求跨轮次留痕。** 核验不通过需回退修订，最多 2 轮，且同一候选须连续两轮通过。这要求跨轮次保留状态、产物哈希与问题项台账，以识别候选是否变化、问题是否消除、修订次数是否耗尽，以及连续通过轮次是否仍属于同一候选。

4. **每日重复执行必须可追溯、可回归。** 需要版本注册表、固定基线与回归检查，以判断某次改动是改进了还是退化了。人工批准记录须具名、带有效期、绑定具体版本，并与版本记录分离保存，防止版本内容变化后沿用旧批准，或将验收通过误当作发布授权。

**结论：本任务不属于「单次提示词或单次报告更新」，而是一个跨阶段、跨交易日、需保留状态且可恢复的持续工作流。**
