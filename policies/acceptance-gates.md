# 日评验收门槛与修订策略

## 冻结声明

- 策略版本：`1.0.0`
- 状态：**已冻结**
- 冻结时点：编写实现代码及查看任何测试结果之前。
- 规则依据：`docs/01-task-charter.md` 第六节。
- 后续不得根据候选日评或测试结果调宽门槛；任何变更必须单独提出并留下变更记录。

## 冻结阈值

| 门槛 | 冻结规则 | 通过阈值 |
| --- | --- | --- |
| 数据新鲜度 | 快照日期必须等于预期交易日，四模块所需字段必须齐全 | 日期偏差为 0；缺失字段数为 0 |
| 数值一致性 | 日评正文中的每个数字必须能在确定性计算结果中找到且相等 | 未匹配或不相等的数字数为 0；数值容差为 0 |
| 模块完整性 | 必须包含票据供给、缺口分析、票据利率、资金面四个模块，不得出现指标结果之外的数字 | 缺失模块数为 0；指标结果之外的数字数为 0 |
| 时点合规 | 所有字段的可得时点不得晚于报告信息截止时点 | 晚于截止时点的字段数为 0 |
| 可恢复 | 中断后必须从已核验检查点继续，不重复已完成的采集与计算 | 重复执行的已完成采集或计算任务数为 0 |
| 连续核验 | 同一候选日评必须连续通过两轮独立核验 | 连续通过轮次至少为 2；不同候选的通过轮次不得合并计数 |

## 有界修订回路

- 每份报告的 S4 → S3 回退最多 **2 次**。
- 每次回退必须由 Orchestrator 生成修复任务包。
- 候选日评内容发生变化后，必须作为新候选重新累计连续两轮核验通过次数。
- 达到回退上限仍未满足发布门槛时，停止自动修订并转人工处理，不得发布。
- 未通过 S4 或未满足连续两轮核验通过的候选日评，不得进入 S5 人工批准发布。
